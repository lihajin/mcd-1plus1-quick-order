# 麦麦 1+1 一键下单（电脑小白版）

把"打开 App → 找 1+1 → 选两件 → 结算 → 付款"压缩成"说一句话"。
设计原则：**人只说人话，复杂的事交给 AI 和麦当劳 MCP。**

## 前置条件（一次性）
- 用户已在 WorkBuddy 配置并启用 `mcd-mcp` 连接器（麦当劳 MCP Token 由用户自行申请，步骤见仓库 README）。
- 本 skill 通过 `mcd-mcp` 工具完成点餐，**绝不在任何文件或消息中写入真实 Token、手机号、地址等敏感信息**。

## 两种运行模式

### 模式一：首次配置（selection.json 不存在，或用户说"改/换/重新设置"）
目标：用最少的提问，把"组合 + 默认就餐方式 + 门店/地址"一次性记好。

1. 用最口语的方式开场，不要抛菜单、不要讲概念：
   > "你想常吃哪款 1+1？直接照你平时说的告诉我就行，比如'吉士蛋麦满分加小薯条'，要不要外送也顺带说一声，剩下的我来查。"
2. 拿到用户的大白话后，调用 `query-meals`（经 mcd-mcp）拉取当前门店可售菜单，
   用**模糊匹配**把用户说的菜名对应到系统里的真实商品（code + name）。
   - 若一句里同时说了主餐和小食/饮品，直接进入第 3 步确认。
   - 若只说了一样，或说不清，给 2~3 个最贴近的选项让用户回数字即可（不要列全表）。
3. 一句话回显确认，让用户用"对/好/行/就这个"之类任意肯定词确认：
   > "我帮你认定成：主餐【吉士蛋麦满分】+ 小食【薯条(小)】，合 12 元。对吗？"
4. 确认后，最简地问就餐方式与地点（一步问完，不要分两轮）：
   > "一般怎么拿？回'到店'、'外送'，或者直接说店名/地名（比如'公司楼下那家'）。"
   - 到店/堂食：调用 `query-nearby-stores`，把用户说的店名/地名模糊匹配到门店，记录 `store.code` 与 `store.name`。
   - 外送：调用 `delivery-query-addresses`，匹配到默认配送地址，记录 `delivery_address.id` 与 `delivery_address.name`。
   - 若匹配不到，给 2~3 个候选让用户回数字。
5. 写入本 skill 目录下的 `selection.json`（结构见下），并告诉用户：
   > "搞定！以后你给这个 skill 发随便一句话，比如'来'，我就直接帮你下好单，把付款页发你。"

`selection.json` 结构：
```json
{
  "version": 1,
  "dine_mode": "takeaway | delivery | counter",
  "store": { "code": "...", "name": "..." },
  "delivery_address": { "id": "...", "name": "..." },
  "combo": {
    "group_a": { "code": "...", "name": "..." },
    "group_b": { "code": "...", "name": "..." }
  },
  "updated_at": "2026-10-10T12:00:00+08:00"
}
```

### 模式二：一键下单（selection.json 已存在）
**默认行为：无论用户发来什么（"来""你好""1"、表情、甚至空话），都直接执行下单流程。**
仅当用户明确说"修改/换/重新设置/不要下单/取消"时，才退回模式一。

下单流程（全程自动，不打断用户）：
1. 读取 `selection.json`。
2. 按 `dine_mode` 取门店/地址 code；若缺失则就近用 `query-nearby-stores` / `delivery-query-addresses` 让用户补选。
3. 调用 `query-meals` 复核两件组合品的**当前在售 code**（菜单会变，以实时为准）。若某件已停售，提示并退回模式一。
4. （可选）`query-store-coupons` / `query-my-coupons` 看有无可叠加优惠，`calculate-price` 试算，向用户展示"主餐 + 小食/饮品 = 12 元"及应付总额。
5. 调用 `create-order` 创建订单，传入门店/就餐方式/商品列表，拿到**订单详情与支付链接（paymentUrl）**。
6. 以最醒目方式呈现：订单摘要（组合、门店/地址、金额）+ 支付链接，引导用户一键直达付款页完成支付。

## 安全与边界
- 本 skill 只负责"创建订单并返回支付链接"，**不自动扣款**；真实支付由用户在支付页完成。
- 不在任何输出或文件写入真实 Token、手机号、地址明细等敏感信息；配置文件仅用占位符。
- 若 `create-order` 失败（库存/营业时间/Token 失效等），如实回显错误码与建议，**不伪造成功**。
- 餐品、价格、供应状态一律以麦当劳官方实时返回为准。

## 存储位置
`selection.json` 与本文件同级（skill 根目录）。可用 `scripts/selection_store.py` 读写校验、`scripts/order_builder.py` 本地构造并校验下单骨架（dry-run，不发起真实请求）。
